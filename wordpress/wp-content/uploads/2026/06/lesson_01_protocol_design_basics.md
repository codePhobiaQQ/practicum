# Урок 1: Основы проектирования криптопротоколов

## Введение

Криптографический протокол — это формальная последовательность шагов, в которой два или более участников обмениваются сообщениями для достижения общей цели безопасности: аутентификации, установки ключа, конфиденциальной передачи данных и т.д.

---

## 1. Что такое криптопротокол

Протокол определяется тремя компонентами:

- **Участники (principals)** — стороны, участвующие в обмене (Alice, Bob, сервер, клиент).
- **Сообщения** — упорядоченная последовательность передаваемых данных.
- **Цель безопасности** — то, что протокол должен гарантировать по завершении.

### Пример: простой протокол аутентификации

```
1. Alice → Bob : Alice, Nonce_A
2. Bob   → Alice: {Nonce_A, Nonce_B, Bob}_K_A
3. Alice → Bob : {Nonce_B}_K_B
```

Здесь `{M}_K` означает шифрование сообщения `M` ключом `K`.

---

## 2. Модели угроз

При проектировании протокола необходимо явно задать **модель злоумышленника (adversary model)**:

| Модель | Возможности противника |
|---|---|
| **Dolev-Yao** | Полный контроль над сетью: перехват, подмена, воспроизведение |
| **Пассивный противник** | Только прослушивание канала |
| **Активный противник** | Изменение, удаление, вставка сообщений |
| **Инсайдер** | Легитимный участник с вредоносными целями |

> **Важно:** Большинство реальных атак эксплуатируют несоответствие между предполагаемой и реальной моделью угроз.

---

## 3. Свойства безопасности

Основные свойства, которые должен обеспечивать протокол:

### Аутентификация
Гарантия того, что сторона является именно тем, за кого себя выдаёт.

- **Взаимная аутентификация** — обе стороны подтверждают личность друг друга.
- **Односторонняя аутентификация** — только одна сторона проходит проверку.

### Конфиденциальность (Secrecy)
Данные недоступны никому, кроме авторизованных участников.

### Perfect Forward Secrecy (PFS)
Компрометация долгосрочных ключей не раскрывает данные прошлых сессий.

### Свежесть (Freshness)
Защита от атак воспроизведения (replay attacks) с помощью одноразовых чисел (nonce) или меток времени.

---

## 4. Типичные уязвимости

### Атака отражения (Reflection Attack)

```
1. Alice → Bob  : Alice, Nonce_A
2. Mallory→ Alice: Alice, Nonce_A   ← отражает первое сообщение обратно
3. Alice → Mallory: {Nonce_A, ...}  ← Alice аутентифицирует себя перед собой
```

**Защита:** разделять роли в протоколе (инициатор/ответчик), использовать разные ключи.

### Атака воспроизведения (Replay Attack)

Противник сохраняет легитимное сообщение и отправляет его позже.

**Защита:** включать в сообщения nonce или timestamp, проверять свежесть.

---

## 5. Принципы проектирования (по Абади и Нидхему)

1. Каждое сообщение должно явно указывать, что именно подтверждается.
2. Ключ, используемый для шифрования, должен быть предназначен именно для этой цели.
3. Идентичности участников должны быть явно включены в подписанные данные.
4. Временны́е метки и nonce должны быть частью каждого аутентифицированного сообщения.

## Практическое задание

1. Найдите уязвимость в следующем протоколе и опишите атаку:
   ```
   1. A → B : A, Na
   2. B → A : {Na}_K_AB
   3. A → B : {Nb}_K_AB
   ```
   *(Подсказка: откуда A знает, что Nb — свежее число от B?)*

2. Модифицируйте протокол так, чтобы устранить найденную уязвимость.

## Итоги урока

- Криптопротокол — формальная система взаимодействия участников для достижения цели безопасности.
- Модель Dolev-Yao — стандартная модель мощного противника в анализе протоколов.
- Ключевые свойства: аутентификация, конфиденциальность, PFS, свежесть.
- Типичные ошибки: атаки отражения и воспроизведения.
